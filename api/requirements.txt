# Vercel installs the requirements.txt sitting NEXT TO the function, with
# the function directory as the working directory -- so a relative path
# dependency such as "../backend" cannot be resolved here. The application
# package is therefore vendored into api/app/ by scripts/sync_api.sh, and
# only third-party packages are listed below.
#
# The Starlette upper bound is load-bearing, not lazy pinning: Starlette
# 1.x changed router internals so that `include_router` silently attaches
# no routes. The app still boots and serves /docs while every business
# endpoint disappears -- no error, no warning.
